# Terminal And Tasks Features

## Capabilities

- Integrated terminal lifecycle and terminal editor/panel placement.
- Shell integration, command detection, links, quick fixes, suggestions, type-ahead, accessibility, and terminal chat tooling.
- Task detection, task definitions, problem matchers, and terminal output integration.
- npm/grunt/gulp/jake task provider support.
- External terminal integration.

## Boundaries

- Debug pre/post task usage is documented under `debugging`.
- Problems generated by task problem matchers are documented under `problems-output-logs`.
- Chat terminal participants/tools are documented under `ai-chat-inline-assistance`.

### How To Extend Safely

1. Start from the source ownership paths above.
2. Use `rg` to find command IDs, context keys, settings, and services before editing.
3. Keep user-facing labels localized through the local source pattern.
4. Register disposables immediately when adding listeners, watchers, providers, or widgets.
5. Add source-level docs here when adding a new command, endpoint, storage file, network URL, or UI surface.
6. Validate the broad surface, not just the changed file: command palette, menu placement, keyboard focus, empty state, error state, and logs.

## Concrete Verification Matrix

Use this section as a no-shortcuts review grid for Terminal Tasks / features.

| Check | Evidence to collect | Pass condition |
|---|---|---|
| Source owner | Full absolute path from the deep-dive source list | The path exists or the doc explicitly says why it is dynamic/provider-owned. |
| Command/menu wiring | `rg -n "registerAction2|MenuId|CommandsRegistry|contributes|commands" <source paths>` | Every user action has a concrete registration point. |
| Context gating | `rg -n "ContextKey|when:|precondition|activationEvents" <source paths>` | Hidden/conditional UI is explained by a context key, activation event, or capability. |
| User-facing text | `rg -n "localize\(|localize2\(|title:|aria-label|tooltip" <source paths>` | Labels are localized or intentionally extension-manifest owned; icon-only UI has accessible naming. |
| Failure path | `rg -n "showErrorMessage|showWarningMessage|logService|output|reject|throw new Error" <source paths>` | Failures have an observable message, log, output channel, or returned error. |
| State persistence | `rg -n "storage|StorageScope|setItem|getItem|workspaceState|globalState|configuration" <source paths>` | Persisted state has an owner and does not reuse another component's private key. |
