# Comments And Review UI

## Visible Surfaces

- Comment threads in editors and review-style views.
- Comment glyphs, overview ruler markers, and thread widgets.
- Review commands contributed by Backboard Chat for reviewing staged/unstaged/file changes.
- Apply/discard suggestion controls for chat-assisted review suggestions.

## UI Elements

- Editor comment ranges and comment thread controls.
- Comments view or comment-driven panes contributed through the comments workbench area.
- Chat review actions: apply, apply and next, discard, discard and next, discard all, next/previous suggestion, continue in chat, and continue in inline chat.
- Helpful/unhelpful feedback controls for review suggestions.

## State Indicators

- Resolved/unresolved comment thread state.
- Pending review suggestion count and current suggestion position.
- Review suggestion applied/discarded state.
- Context keys that show review commands only when there is a current review context.

## Source Anchors

- `src/vs/workbench/contrib/comments`
- `extensions/copilot/package.json`
- `src/vs/workbench/contrib/chat`

### UI Audit Checklist

- Every visible action should map to a command ID, menu registration, or extension contribution.
- Every icon-only action needs a title, tooltip, ARIA label, or hover description in the owning source.
- Every tree/list/editor surface needs a clear empty state and a clear failure state.
- Every hidden or conditional UI element needs an explicit context key or capability gate.
- Every color, icon, and spacing decision should use workbench theme variables where possible.
